API仕様の壁打ちと確認・更新を行います。以下のステップを順番に実行してください。

## Step 1: API選択

`docs/api/endpoints.md` を読み込み、エンドポイント一覧をグループ別に整理してユーザーに提示してください。

提示フォーマット：
```
どのAPIの仕様を確認しますか？

### 認証系
1. POST /v1/auth/login - ログインAPI
2. POST /v1/auth/refresh - アクセストークン再発行API
3. DELETE /v1/auth/logout - ログアウトAPI

### ユーザー系
...（以下同様）

番号で選択してください。
```

ユーザーが選択したら Step 2 へ進みます。

## Step 2: ドキュメント読み込み（サブエージェント）

選択されたAPIのドキュメントファイルを特定し、`agents/doc-reader.md` のエージェント定義を使ってサブエージェントを起動し、ファイルを読み込ませます。

### ドキュメントパスのマッピング規則

`references/endpoints.md` に記載されたエンドポイントは以下のパス構造に対応します：

| エンドポイントのパス | ドキュメントディレクトリ |
|---|---|
| `/v1/auth/*` | `docs/api/auth/` |
| `/v1/users/*` または `/v1/me` 系ユーザー | `docs/api/users/` |
| `/v1/books/*` | `docs/api/books/` |
| `/v1/users/:username/books/*` または `/v1/me/books/*` | `docs/api/user_books/` |
| `/v1/me/follows/*` または `/v1/users/:username/follow*` | `docs/api/follows/` |
| `/v1/me/likes/*` | `docs/api/likes/` |
| `/v1/tags` または `/v1/me/tag_follows/*` | `docs/api/tags/` または `docs/api/tag_follows/` |
| `/v1/feed*` | `docs/api/feed/` |

ファイル名はアクション（create/show/index/update/destroy/login/logout/refresh など）に対応します。

`agents/doc-reader.md` を使ったサブエージェント起動例：
```
agents/doc-reader.md の定義に従い、以下のファイルを読み込んで内容をそのまま返してください：
file_path: docs/api/[対象ディレクトリ]/[対象ファイル].md
```

## Step 3: 内容共有と壁打ち

サブエージェントが返した内容を以下の構成でユーザーに提示します：

```
## [API名] の現在の仕様

[ドキュメントの内容をそのまま表示]

---

## 確認・議論したいポイント

以下について一緒に確認しましょう：

**1. リクエスト仕様**
- [気になる点・曖昧な点を具体的に挙げる]

**2. レスポンス仕様**
- [気になる点・曖昧な点を具体的に挙げる]

**3. エラーハンドリング**
- [気になる点・曖昧な点を具体的に挙げる]

**4. 認証・権限**
- [気になる点・曖昧な点を具体的に挙げる]

何か変更したい点や追加したい要件はありますか？
```

確認ポイントは実装時に問題になりそうな箇所を重点的に挙げてください。例：
- パラメータのバリデーション条件が未定義
- エラーケースが網羅されていない
- 認証の挙動が不明確
- ページネーションの仕様がない

## Step 4: 更新計画の立案と提示

ユーザーとの壁打ちで更新が必要と判断した場合、変更内容を計画してから提示します。

提示フォーマット：
```
## 更新計画

以下の変更を行います：

### 変更点

**[セクション名]**
- 変更前: [現在の記述]
- 変更後: [提案する記述]
- 理由: [なぜこの変更が必要か]

**[セクション名]**
...

この内容でドキュメントを更新してよいですか？
```

更新不要ならその旨を伝えて終了します。

## Step 5: ドキュメント更新

ユーザーが承認したら、Edit ツールを使って実際のドキュメントファイルを更新します。

更新後：
```
## 更新完了

`docs/api/[パス]` を更新しました。

### 変更箇所
- [変更した内容のサマリー]

このAPIの実装に進む準備が整いました。
```

## 壁打ちの進め方

- ユーザーの回答に応じて Step 3 ↔ Step 4 を繰り返しても構いません
- 一度に多くの質問を投げず、重要な点から優先して確認する
- ユーザーが「これでOK」「問題ない」と言ったら次のステップへ進む
- 技術的に実装困難な仕様が出てきたら、代替案を提示する
