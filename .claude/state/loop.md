- 2026-08-09 #136: **プレフライト検査は通ったが、実装して初めて契約の矛盾が判明した。**
  完了条件が既存 request spec 4件を「無修正で通る」と固定していたが、それらは
  `allow(TokenIssuer).to receive(:decode).with("valid_token")` で stub しており、
  RSpec の verifying partial double が**実装の引数シグネチャを検証する**ため、
  `decode` に必須キーワード引数を足した時点で stub の定義自体が
  `Missing required keyword arguments: purpose` で落ちる。呼び出し側の書き換えとは無関係。
  → **プレフライト検査に追加すべき項目**: 「完了条件が『既存 spec を無修正で通す』と
    書いているとき、その spec が変更対象のメソッドを stub していないか」。
    stub していれば、シグネチャ変更と無修正通過は原理的に両立しない。
  さらに**2つ目の欠陥**: `refresh_tokens.token` が `varchar(128)` で、`purpose` クレームを
  足すと JWT が上限を超え `PG::StringDataRightTruncation` になる（9件失敗）。
  カラム拡張には新規マイグレーションが要るが、`db/migrate/**` は「触ってはいけない
  ファイル」で、新規追加も「触ってよいファイル」に無い。
  → **起票時にペイロードを増やす変更は、格納先カラムの桁数を確認する**必要がある。
  → **人間の判断で契約を広げて解決した（選択肢 A）。** 既存 spec 4件の stub 更新と
    `db/migrate/` の新規追加を許可してもらい、5ゲート合格まで到達して PR #141 を ready にした。
- 2026-08-09 #138: **契約が「触ってよい」としたファイルを、強制層（C層）が触らせなかった。**
  完了条件に `.env.example` への環境変数6件の追加があり、「触ってよいファイル」にも入っていたが、
  `.claude/settings.json` の `deny` にある `Read(/.env*)` が `.env.example` にも一致するため、
  Read ツール・`cat`・追記の3通りすべてが拒否された。Edit ツールは事前 Read を要求するので
  deny を回避できない。**実装の失敗ではなく、契約と強制層の衝突。**
  → **プレフライト検査に追加すべき項目**: 「『触ってよいファイル』が `settings.json` の
    `deny` パターンに一致していないか」。とくに `.env.example` は
    `Read(/.env*)` に**意図せず巻き込まれる**（秘密情報の保護が目的のルールなのに、
    公開テンプレートまで止まる）。
  → 恒久対応の候補は2つ。①deny を `Read(/.env)` `Read(/.env.local)` に絞る
    ②環境変数の追記は人間の手作業と割り切り、issue の完了条件に入れない。
