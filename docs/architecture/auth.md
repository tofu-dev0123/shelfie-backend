# 認証フロー

## 概要

Shelfie バックエンドはステートレスな JWT 認証を採用します。
セッション管理は行わず、アクセストークンとリフレッシュトークンの 2 トークン方式でユーザー認証を管理します。

---

## 認証方式

### フロント主導の OAuth フロー

フロントエンド（Next.js）が Google OAuth を処理し、取得した ID トークンをバックエンドに送信します。
バックエンドは ID トークンを検証し、独自の JWT を発行する責務のみを持ちます。

```
┌─────────────┐         ┌───────────────┐         ┌─────────────────┐
│   Next.js   │         │  Google OAuth │         │   Rails API     │
└──────┬──────┘         └───────┬───────┘         └────────┬────────┘
       │                        │                          │
       │  ① Googleログインボタン押下                        │
       │─────────────────────>  │                          │
       │                        │                          │
       │  ② Google認証完了・IDトークン取得                  │
       │<─────────────────────  │                          │
       │                        │                          │
       │  ③ IDトークンをバックエンドに送信                   │
       │──────────────────────────────────────────────────>│
       │                        │                          │
       │                        │  ④ IDトークンをGoogleで検証
       │                        │<─────────────────────────│
       │                        │  ⑤ 検証結果              │
       │                        │─────────────────────────>│
       │                        │                          │
       │                        │          ⑥ User レコード作成 or 取得
       │                        │                          │
       │  ⑦ アクセストークン + リフレッシュトークンを返却    │
       │<──────────────────────────────────────────────────│
```

---

## 2トークン方式

「ログインしっぱなし」の UX を実現するため、有効期限の異なる 2 種類のトークンを運用します。

| トークン | 有効期限 | 用途 |
|---|---|---|
| アクセストークン | 60 分 | API リクエストの認証 |
| リフレッシュトークン | 30 日 | アクセストークンの再発行 |

### トークンの保存場所

| トークン | 保存場所 | 理由 |
|---|---|---|
| アクセストークン | メモリ or localStorage | 短命のためリスクが低い |
| リフレッシュトークン | **HttpOnly Cookie** | JavaScript からアクセス不可にし、XSS 攻撃を防ぐ |

## 通常リクエストのフロー

```
Next.js                              Rails API
  │                                      │
  │  APIリクエスト（Authorizationヘッダーにアクセストークン付与）
  │─────────────────────────────────────>│
  │                                      │ アクセストークンを検証
  │        レスポンス                    │
  │<─────────────────────────────────────│
```

---

## トークン再発行フロー（サイレントリフレッシュ）

アクセストークンが期限切れになった場合、ユーザーに意識させることなく自動で再発行します。

```
Next.js                              Rails API
  │                                      │
  │  APIリクエスト（期限切れのアクセストークン）
  │─────────────────────────────────────>│
  │                                      │
  │  401 Unauthorized                    │
  │<─────────────────────────────────────│
  │                                      │
  │  リフレッシュリクエスト（HttpOnly Cookie のリフレッシュトークン）
  │─────────────────────────────────────>│
  │                                      │ リフレッシュトークンを検証
  │  新しいアクセストークン               │
  │<─────────────────────────────────────│
  │                                      │
  │  元のAPIリクエストをリトライ          │
  │─────────────────────────────────────>│
```

---

## ログアウトフロー

```
Next.js                              Rails API
  │                                      │
  │  ログアウトリクエスト                 │
  │─────────────────────────────────────>│
  │                                      │ リフレッシュトークンを無効化
  │                                      │ Cookie を削除
  │  200 OK                              │
  │<─────────────────────────────────────│
  │                                      │
  │  アクセストークンをメモリから削除     │
```

> リフレッシュトークンはDBで管理し、ログアウト時に無効化することで強制ログアウトを実現します。

## 使用 gem

| gem | 用途 |
|---|---|
| `google-auth-library-ruby` | Google ID トークンの検証 |
| `jwt` | アクセストークン・リフレッシュトークンの発行・検証 |
