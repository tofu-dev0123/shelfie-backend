# ユーザー登録（サインアップ）フロー

## 概要

Clerk による Google 認証後、プロフィール設定（nickname / username）を完了してからバックエンドに User レコードを作成します。

---

## 登録フロー

### 新規ユーザーの場合

```
┌─────────────┐         ┌───────────┐         ┌─────────────────┐
│   Next.js   │         │   Clerk   │         │   Rails API     │
└──────┬──────┘         └─────┬─────┘         └────────┬────────┘
       │                      │                         │
       │  ① Google ログインボタン押下                    │
       │─────────────────────>│                         │
       │                      │                         │
       │  ② Google 認証完了・Clerk セッション確立        │
       │<─────────────────────│                         │
       │                      │                         │
       │  ③ GET /v1/me（Clerk JWT）                     │
       │──────────────────────────────────────────────> │
       │                      │         Clerk JWT 検証  │
       │  ④ 404 Not Found（User レコードなし）           │
       │<────────────────────────────────────────────── │
       │                      │                         │
       │  ⑤ プロフィール設定画面へリダイレクト           │
       │  （nickname 入力欄に Clerk から取得した         │
       │    Google 表示名をプリフィル）                  │
       │                      │                         │
       │  ⑥ username 入力のたびに重複チェック（デバウンス）         │
       │  GET /v1/users/username/check?value=xxx         │
       │──────────────────────────────────────────────> │
       │  { "available": true/false }                   │
       │<────────────────────────────────────────────── │
       │                      │                         │
       │  ⑦ 確定ボタン押下                              │
       │  POST /v1/users（Clerk JWT + nickname + username）
       │──────────────────────────────────────────────> │
       │                      │         Clerk JWT 検証  │
       │                      │  clerk_user_id・email 取得
       │                      │         User レコード作成
       │                      │  アクセストークン + リフレッシュトークン発行
       │                      │  リフレッシュトークンを DB に保存
       │                      │                         │
       │  ⑧ アクセストークン（レスポンスボディ）         │
       │     リフレッシュトークン（HttpOnly Cookie）      │
       │<────────────────────────────────────────────── │
       │                      │                         │
       │  ⑨ アクセストークンをメモリに保存              │
       │     ホーム画面へリダイレクト                    │
```

---

## 途中離脱後の再訪問フロー

Clerk 認証済みだが User レコード未作成の状態でブラウザを閉じ、再度アクセスした場合。

```
ページ読み込み
    ↓
Clerk SDK が Cookie を確認（自動）
    ↓
isSignedIn: false ─→ ログイン画面へ
isSignedIn: true
    ↓
GET /v1/me（Clerk JWT）
    ↓
200 OK      ─→ ホーム画面へ（通常のログイン済み状態）
404 Not Found ─→ プロフィール設定画面へ（サインアップを再開）
```

### セッション状態と画面遷移まとめ

| Clerk セッション | バックエンド User レコード | 遷移先 |
|---|---|---|
| なし | - | ログイン画面 |
| あり | なし | プロフィール設定画面 |
| あり | あり | ホーム画面 |

---

## username 重複チェック API

| 項目 | 内容 |
|---|---|
| エンドポイント | `GET /v1/users/username/check?value={username}` |
| 認証 | 不要（パブリックエンドポイント） |
| レスポンス | `{ "available": true }` / `{ "available": false }` |
| フロント実装 | デバウンス（300〜500ms）でリクエスト数を抑制 |
| セキュリティ | レートリミットを適用し、username 列挙攻撃を防止 |

---

## Clerk JWT から取得するユーザー情報

| Clerk JWT クレーム | 取得内容 | 用途 |
|---|---|---|
| `sub` | Clerk ユーザー ID | `clerk_user_id` として DB に保存 |
| `email` | メールアドレス | `email` として DB に保存 |
| `name` | Google アカウントの表示名 | nickname 入力欄にプリフィル（DB には保存しない） |
