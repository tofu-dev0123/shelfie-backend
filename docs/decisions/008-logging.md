# 008: ログ設計方針

## 決定日

2026-03-06

## ステータス

決定済み

## 決定内容

### 出力先は標準出力（stdout）

Railwayはコンテナのstdoutをキャプチャしてログビューアで閲覧できる。ログファイルへの書き込みは行わない。

### フォーマットはJSON形式

`lograge` gemを使用してRailsのデフォルトログを1リクエスト1行のJSONに変換する。

### カスタムフィールドに user_id を追加

認証済みリクエストではログに `user_id` を含める。未認証リクエストは `null` になる。

### ログ出力方針

| 種類 | 環境 | レベル |
|---|---|---|
| リクエスト・レスポンス | 全環境 | `INFO` |
| 例外発生時 | 全環境 | `ERROR` |
| 外部API呼び出し（Clerk・楽天書籍API） | 全環境 | `INFO` / `WARN`（失敗時） |
| 認証イベント（ログイン・失敗・リフレッシュ） | 全環境 | `INFO` / `WARN`（失敗時） |
| メソッド入口 | 本番以外 | `DEBUG` |

### ログレベルの使い分け

| レベル | 使う場面 |
|---|---|
| `DEBUG` | メソッド入口ログ（本番以外のみ） |
| `INFO` | リクエスト・認証成功・外部API成功など正常な処理 |
| `WARN` | 認証失敗・外部APIエラーなど異常だが継続できる場合 |
| `ERROR` | 例外発生時など対応が必要なエラー |
