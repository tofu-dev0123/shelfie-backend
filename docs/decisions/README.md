# アーキテクチャ決定記録（ADR）

設計上の判断とその理由を、決めた時点の文脈ごと残す。

**ADR は歴史的記録である。** 後から方針が変わっても、当時の判断を書き換えない。
書き換えると「なぜそう決めたのか」を辿れなくなり、記録として機能しなくなる。
方針が変わったときは**新しい番号で起票し、古い ADR には手を入れない。**

## 書くとき

- **1 ADR = 1 決定。** 複数の論点を1本に混ぜない
- 全 ADR にある節は `## 決定日` / `## ステータス` / `## 決定内容` の3つ。
  `## 背景` / `## 検討した案` / `## 理由` / `## 例外` は必要に応じて足す
- **選択肢が複数あった決定では、却下した案とその理由を書く。**
  「なぜ採用したか」より「なぜ他を外したか」が後から効く
- 実装の作法は書かない。それは [docs/development/](../development/README.md) の担当
